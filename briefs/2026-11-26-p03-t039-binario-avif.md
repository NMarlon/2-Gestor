  pela URL pública.
- **O comentário das linhas 208–221 está errado e deve ser corrigido.** A
  tentativa anterior de `upload_files` mandava os parâmetros por query string
  (GET). A documentação do cPanel é explícita: o upload é **POST
  `multipart/form-data`**; os campos do arquivo são `file-0`/`file-1` com
  `filename`; `dir` e `overwrite` vão na query. Parâmetro de query com prefixo
  `file-` é descartado — nunca houve arquivo no corpo. A API não mentiu; o
  cliente não enviou nada. Reescreva o comentário com essa causa, sem inventar.
- **Contrato medido/documentado do upload:**
  `POST https://<host>:2083/execute/Fileman/upload_files?dir=<dir>&overwrite=1`
  com os headers `AUTH` + `User-Agent: UA` que já existem no script. Corpo:
  `FormData` com `file-0` = `new Blob([buf])` e o nome no 3º argumento.
  **Não** defina `Content-Type` à mão. **Não** passe `permissions` (o default
  do cPanel é 0644; mandar `0644` como string é risco de validação).
- **Resposta de sucesso:**
  `{"status":1,"data":{"succeeded":1,"failed":0,"uploads":[{"file":"...","status":1,"size":...}]}}`.
  Trate `status!==1`, `failed>0` ou `uploads[0].status!==1` como erro, incluindo
  `reason` na mensagem.
