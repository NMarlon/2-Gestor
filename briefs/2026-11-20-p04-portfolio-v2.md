## 2. Correções obrigatórias

### C-1 · O bloco vazio do case (prioridade máxima)

`.case__viz` renderiza **1068 × 458 px totalmente vazios** em
`projetos/reconhecedor-de-rostos.html`. O maior bloco da página não comunica nada
e lê como imagem quebrada.

**Faça:** substituir a área vazia por um diagrama de pipeline em HTML/CSS puro
(sem imagem), com os três estágios reais do sistema:
`detecção de rosto → embedding (ArcFace) → agrupamento por pessoa`.
Cada estágio com um rótulo mono, uma frase curta e uma seta entre eles.
Altura máxima 260 px. Se preferir não desenhar diagrama, reduza o bloco a uma
faixa de 240 px com os três números do case. **Não deixe área vazia.**

Aplicar o mesmo critério nos outros cinco cases: onde hoje há bloco sólido com o
nome do projeto, ele deve ter no máximo 240 px de altura e conter o nome em mono
mais o status (`No ar`, `Em uso`, `Protótipo`) — não um retângulo grande e mudo.

### C-2 · Régua com duas gramáticas no mesmo bloco

No `.stats` da home, `border-top` usa `var(--ink)` (contraste 16:1, a linha mais
clara da página) e `border-bottom` usa `var(--rule)` (1,4:1). Duas réguas
diferentes no mesmo bloco.

**Faça:** usar `var(--rule)` nas duas. Réguas são divisão discreta, não moldura.

### C-3 · `.hero__note` em 10,56 px

Caixa-alta, mono, com tracking — a 10,56 px fica abaixo do confortável.
**Faça:** no mínimo `0.78rem` (12,5 px), e aumentar o `line-height` para 1.6.

### C-4 · Ficha do case com linhas de altura irregular

Em `.case__numbers`, as linhas medem 51, 51 e 65 px porque a descrição de "0,29 s"
quebra em três linhas.
**Faça:** grid de duas colunas com o valor alinhado à linha de base e altura

**Faça:** manter o `h1` grande, mas ocupar a coluna à direita com um bloco de

## 3. Correção defensiva (obrigatória, mas simples)

Conteúdo abaixo da dobra depende de `IntersectionObserver` para sair de
`opacity: 0`. Se o observer não disparar (aba em segundo plano, navegador antigo,
extensão), a seção fica invisível para sempre.

**Faça:** um fallback de 1,5 s que adiciona `.is-visible` a tudo que ainda não
revelou, mais um `<noscript>` já existente ou equivalente. Conteúdo invisível é
pior que animação ausente.

## 6. Captura de tela — leia antes de fotografar

`--window-size` **não** funciona neste Edge headless. Para o print de 390 px é
preciso CDP:

```
Emulation.setDeviceMetricsOverride { width: 390, height: 844, deviceScaleFactor: 2, mobile: true }
```

E antes do print, forçar o reveal:

```
Emulation.setEmulatedMedia { features: [{ name: 'prefers-reduced-motion', value: 'reduce' }] }
```

Sem isso, todo print abaixo da dobra sai em branco e você vai "consertar" um bug
que não existe. Os prints de conferência vão para
`C:\MarlonScripts\2-Gestor\DOCS\P-04-Portfolio\prints\v2-*.png`, não para o repo
do site.
