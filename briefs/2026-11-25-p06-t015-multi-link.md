## O que construir

### 1. `links.json` na raiz do projeto

```json
{
  "links": [
    {
      "id": "por6",
      "nome": "POR6 — Planejamento Missionário",
      "pasta_id": "1-7w0EpMvo8mIWlFcLSjVJEgwaWR5bYdJ",
      "padrao_nome": "POR(\\d+(?:\\.\\d+)*)\\.pdf",
      "frequencia_min": 1440,
      "ativo": true,
      "criado_em": "2026-11-25T21:00:00-03:00"
    }
  ]
}
```

- `id`: slug `[a-z0-9-]{2,32}`, único, imutável.
- `pasta_id`: ID da pasta do Drive (o link `drive.google.com/drive/folders/<pasta_id>`).
- `padrao_nome`: regex que escolhe o arquivo dentro da pasta (opcional; sem ela, o primeiro).
- `frequencia_min`: inteiro ≥ 5.
- **Migração:** crie o `links.json` já com o `por6` tirado do `config.json` atual. Não apague
  o `config.json` — ele continua valendo para o modo sem `--link`.

### 2. `verificar.py --link <id>`

- Lê `links.json`, valida o `id` e usa os caminhos **daquele** link:
  `dados/links/<id>/historico.json`, `dados/links/<id>/snapshots/`,
  `dados/links/<id>/relatorios/`.
- **Sem** `--link`, comportamento atual intacto (`config.json`, `historico.json`,
  `dados/snapshots/`, `relatorios/`). Isso é obrigatório: os testes e o agendador antigo
  dependem disso.
- `--listar-links` imprime uma tabela (`id | nome | frequência | ativo | última leitura`) e
  sai 0.
- `--link` inexistente → sai **2** com `link desconhecido: <id>`.
- Nada de token em disco (regra que já vale).
